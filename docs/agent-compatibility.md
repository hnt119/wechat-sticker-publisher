# Agent compatibility for v0.2.0

All seven adapters distribute the same [Agent Skill](../.agents/skills/wechat-sticker-publisher/SKILL.md). The harness needs access to the album workspace, a shell with `wechat-sticker` on its path, and a writable release directory. Python 3.10+ can run the publisher directly. [Installation commands](agent-installation.md) · [Agent Skills specification](https://agentskills.io/specification)

### Runtime evidence

- **Codex.** Its app-server `skills/list` refresh returned the project's exact, enabled `SKILL.md`. An authenticated ephemeral CLI session with workspace-write access read the skill and workflow reference, checked CLI help, inventoried and validated the chestnut album, and ran `wechat-sticker build --pack chestnut --offline`. It inspected the report and tested the archive with `unzip -t`. In a second scratch album with only the banner removed, the ordinary request “Package my stickers for WeChat publishing” selected the skill. Codex reported `INCOMPLETE`, four of five supplementary images and the missing opaque 750 × 400 banner brief. The partial ZIP passed its integrity check.
- **OpenCode.** `opencode debug skill` returned the project skill's description, path and full body. Its body matched the canonical Markdown. A real `opencode run --pure --model opencode/deepseek-v4.1-flash-free` session invoked the `skill` tool by name, checked CLI help, ran inventory, validation and `build --all --offline`, inspected the reports and previews, and tested the ZIP. A second trial with the packaged installer and the ordinary “Package my stickers for WeChat publishing” request also selected the skill and produced the same ZIP. These sessions used a public sample, a restricted shell policy and the free OpenCode model route. [Tested OpenCode release](https://github.com/anomalyco/opencode/releases/tag/v1.19.6) · [OpenCode model service](https://opencode.ai/docs/zen/)
- **Package comparison.** Codex and OpenCode each reported eight stickers, five supplementary images and zero missing assets. Both ZIPs matched the independent CLI reference byte for byte. - **Claude Code.** After installation from the packaged CLI, a `/wechat-sticker-publisher` print-mode request listed the skill in the initialization event. The expanded user message and model-request record in the local transcript both contained the entire canonical Markdown body. Native `claude auth status` reported signed out, and the session ended before a model response.
- **Gemini CLI.** `gemini skills list` returned the exact project filename, canonical description and enabled state. Using the matching official CLI Core in that workspace, its real `Config`, registry and `ActivateSkillTool` returned the entire canonical body and all three reference names in the model-facing tool result. ## Discovery, invocation and permissions

Install the folder named `wechat-sticker-publisher`, including its references, below a skill root. Its `SKILL.md` supplies a lowercase hyphenated name matching the folder, a description used for selection, and the MIT license. Use the ordinary-language request “Package my stickers for WeChat publishing.” See the matrix above for observed results. The following paths and controls come from each host's documentation. Version-specific evidence is limited to the table above.

| Harness | Project roots | User roots | Discover or invoke |
| --- | --- | --- | --- |
| Codex | `.agents/skills` | `~/.agents/skills` | `/skills` or `$wechat-sticker-publisher` |
| Claude Code | `.claude/skills` | `~/.claude/skills` | Start the prompt with `/wechat-sticker-publisher` |
| Gemini CLI | `.gemini/skills`, `.agents/skills` | `~/.gemini/skills`, `~/.agents/skills` | `gemini skills list`, then ask for the skill by name |
| Cursor | `.cursor/skills`, `.agents/skills` | `~/.cursor/skills`, `~/.agents/skills` | Type `/wechat-sticker-publisher` in Agent chat |
| OpenCode | `.opencode/skills`, `.agents/skills`, `.claude/skills` | `~/.config/opencode/skills`, `~/.agents/skills`, `~/.claude/skills` | `opencode debug skill` (v1), then ask for the named skill |
| GitHub Copilot CLI | `.github/skills`, `.agents/skills`, `.claude/skills` | `~/.copilot/skills`, `~/.agents/skills` | `copilot skill list`, `/skills info wechat-sticker-publisher`, or mention `/wechat-sticker-publisher` |
| DeepSeek Harness | `.dsh/skills`, `.agents/skills` | `~/.dsh/skills`, `~/.agents/skills` | Open the album workspace and ask for the named skill |

- **Codex** scans from the working directory up to the Git root. Multiple entries with the same name can appear in the selector. A description supports automatic selection. Sandbox and approval settings govern execution. Use a workspace-write session for the export. [Skills](https://developers.openai.com/codex/skills) · [Codex CLI and platform setup](https://developers.openai.com/codex/cli/)
- **Claude Code** discovers project skills along the path to the Git root. For an enterprise, personal and project name collision, enterprise takes priority, then personal. Managed policies can restrict local skills. A normal trusted session with shell permission is sufficient. Claude Code supports macOS, Linux, Windows and WSL subject to its system requirements. [Skills and precedence](https://code.claude.com/docs/en/skills) · [System requirements](https://code.claude.com/docs/en/setup)
- **Gemini CLI** gives workspace skills priority over user skills, then extension and built-in skills. In each user or workspace tier, the shared `.agents` location wins. The agent calls `activate_skill` and requests approval to load the body and references. Workspace trust and shell policy still apply. The tested package declares Node.js 20+ and was run on Node.js 24.22.3. [Discovery and activation](https://geminicli.com/docs/cli/skills/) · [Installation](https://geminicli.com/docs/get-started/installation/)
- **Cursor** also reads Claude and Codex skill folders at project and user scope. User skills in `~/.agents/skills` are local to the machine. For remote agents, place the skill in the project or use a supported sync mechanism. Run in Agent mode with terminal and workspace permissions. [Skills and cloud scope](https://cursor.com/docs/skills) · [CLI installation](https://cursor.com/docs/cli/installation)
- **OpenCode** v1 walks project ancestors up to the worktree. The model uses its `skill` tool to load a definition. Its skill permission can allow, prompt or deny. Shell execution has its own policy. The current v2 documentation has different permission names and discovery rules. Use the documentation matching your installed major version. [Tested v1 skill guide](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/web/src/content/docs/skills.mdx) · [Current guide](https://opencode.ai/docs/skills/)
- **GitHub Copilot** reloads skills with `/skills reload` and injects a selected skill on demand. Approve the specific shell tools your workspace needs. Organization policy can restrict CLI use. The standalone binary supports macOS, Linux and Windows. Installation through npm needs Node.js 22+. Project-scoped skills are also documented for compatible Copilot agent environments. [CLI skills](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-skills) · [Setup and policy](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/install-copilot-cli) · [Copilot agent skills](https://docs.github.com/en/copilot/concepts/customizations/agent-skills)
- **DeepSeek Harness** is a separate runtime with its own registry, model configuration and permission system. In the preview tested, project-native takes priority over project-shared, then runtime, user-native and user-shared roots. Its home settings can redirect the user roots. Enable only the tools needed for local packaging. [DeepSeek Harness guide](deepseek-harness.md) · [Upstream registry](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/skills.md)

## Repeat an end-to-end check

1. Install the candidate CLI into a virtual environment and activate it. Make two fresh copies of [the synthetic album](../examples/sample-album). Use the same CLI, dependency versions and album inputs in both.
2. In the reference copy run `wechat-sticker validate --all` and `wechat-sticker build --all --offline`.
3. In the agent copy install the skill for that host, launch the host there, and ask “Use wechat-sticker-publisher to validate and package this album for WeChat.” Capture the selected skill path, the body-load event, shell commands, exit statuses, report and ZIP.
4. Compare the two album ZIPs with `cmp` or SHA-256. Check the report and supplementary count independently. For a missing-artwork trial, remove a supplementary image **from a separate scratch copy** and check the resulting partial package and brief.
